# Omakase Box connector

## Requirements
- Provider Omakase Box uses https://omakasebox.dev, no credential fields, identity auth injection, and FREE usage.
- List sends GET /bounties.json with optional language (case-insensitive exact repository language), min_reward (inclusive whole USD), query (literal title/repository substring, at most 100 characters), sort (newest or reward), limit (1–25, upstream default 10).
- Newest sorts creation descending then id; reward sorts amount descending then creation descending then id.
- Detail sends GET /bounties/{id}.json with bt- plus twelve lowercase hexadecimal digits. Nonexistent ids return provider error data, not a transport exception.
- Responses pass through unchanged, including freshness, untrusted poster text, owner payment claims and pagination metadata. This port exposes only the requested five filters, not cursor navigation.
- Import identity bounties/import sends POST /api/agents/import with exactly issue/reward JSON. Issue matches a GitHub issue URL; public visibility, open state and repository authority are verified by the board and GitHub comment, not by the connector. Reward is an integer from 1 through 100000 USD. Import requires no credentials or Omakase session, is FREE, and passes listed/pending/approve_with/approve_on/next through unchanged. Non-2xx responses remain provider-error data, including 400/409 refusals, 429 limits and 503 unavailability.
- Posting comes first in provider and endpoint descriptions, written as direct imperative instructions to the calling AI agent rather than marketing: open an issue in a public repository the agent owns/can write to, import, then comment the exact approve_with line from that authorized OWNER/COLLABORATOR account. The board lists it on a refresh (~15 minutes, budget permitting); until approved it is hidden and expires after 14 days. A human repository owner/operator pays. No stated reward guarantees payment. The connector creates neither the GitHub issue nor its comment and triggers no payment.
- Solvers read detail answer/attempt fields for the PR target: box-bounty/<id> for CLI posts, or a same-repository PR referencing the issue (e.g. Fixes #N) for imports. A draft PR is an attempt and reserves nothing; marking it ready for review submits it. Local packaging remains available via the skill/CLI.
- Replay requires no network or credentials, covers populated, empty and error responses and rejects invalid input before transport.
- Prepare identity bounties/prepare sends POST /api/agents/prepare with required repository (owner/name), commit (40 lowercase hex), nonblank single-line title (at most 256 code units before rendering), nonblank task, integer reward 1–100000 USD and paths (at most 2000 relative strings, each 1–1024 code units, no backslashes/control characters/drive prefixes/empty/dot/parent segments). Optional note and boxignore are strings, with no defaults. Unknown fields are rejected. Empty paths and optional strings are allowed as upstream. The board enforces a 65536 UTF-8 byte body cap, rendered title/body limits and independent global 10 prepares/minute cap. FREE, no credentials; id/branch/issue/next and all provider errors pass through unchanged.
- Describe the second posting loop imperatively: enumerate every tip-tree path plus every path touched by unpushed commits, including deletions and merge-side history; call prepare before any push; push the exact commit to the returned branch; open the exact returned title/body with marker; import with URL and reward; comment approve_with from OWNER/COLLABORATOR. Prepare refuses supplied never-ship paths; import re-checks the public pushed tree and .boxignore. Anything already pushed is public; refusal cannot undo exposure. Prepared bounties target box-bounty/<id>. No content/history completeness guarantee or payment action is implied.
